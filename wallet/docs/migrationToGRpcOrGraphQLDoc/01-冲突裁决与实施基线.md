## 2. 两套方案的冲突与结论

| 编号 | 旧钱包方案／归档方案差异 | 权威事实与本项目结论 | 合并修正 |
| --- | --- | --- | --- |
| C01 | 通用标准读推荐 gRPC；归档方案资产页要求 GraphQL | 官方两种客户端均支持 Core 标准读，选择不受前端／后端标签限制。钱包资产多资源一致快照采用 GraphQL；发送前可花费校验、gas 与构建采用 Fullnode。属于项目语义选择 | 03、04、09、12 区分展示与发送 |
| C02 | 钱包内接新 dApp Kit 或兼容层；归档方案自有 Provider | 新 Kit 面向 dApp 连接钱包，不能替代插件账户授权／签名。插件自有 Provider 与领域 Hook，demo 用现代 Kit 两包，删除旧 Kit 依赖 | 04、10、12、13 |
| C03 | 旧方案允许故障切回 JSON-RPC；归档方案不长期保留 | 官网允许渐进维护旧 endpoint，并非 RTD 必须这样做。当前项目原地替换且未上线，按已授权目标不提供 fallback；回滚发布与暂停能力保留 journal | 02、03、07、13 |
| C04 | 长历史只由 GraphQL／服务端归档读取；归档方案 Chrome 三入口 | 官方 Archival Ledger／MovePackage 与 Fullnode State／Execution 职责独立；Fullnode 无隐式历史回退。钱包显式归档 reader，必须提供 gRPC-Web 桥接、同链和覆盖证据 | 03、08、09、12 |
| C05 | 旧短 chain identifier、SDK network 标签和 H0 混用 | 固定官方 types 定义完整 32-byte base58 H0 digest，gRPC 从 GetServiceInfo.chainId，GraphQL 从 checkpoint(0).digest；本地实现一致。锁键采用完整 H0 + generation + account，标签／URL 不替代链身份 | 05、06、08 |
| C06 | 历史运行快照没有 GraphQL；归档方案已部署子服务 | 9 月 24 日与 10 月 2 日是不同快照，不能同时当当前运行状态。GraphQL 由 rtd-archive-service 子服务提供，是否当前可用需要重新查部署绑定与真实请求 | 08、11；历史事实明确标时间 |
| C07 | From+To、affectedAddress、sender 与全账户活动近似替换 | 官方 sender 仅发送者；原生 affectedAddress 不自动等价全部收支。账户完整历史用独立 accountHistory 扩展并核验证书；游标不跨端点混用 | 04、06、08、12、13 |
| C08 | getStakes／APY 直接改名，或归档具治理服务 | 新 SDK 无这些直接替代。GraphQL 组合系统／pool／rate，按锁定治理算法实现领域读，缺历史显示未知；构建质押／赎回仍 Fullnode | 04、08、12 |
| C09 | 保存 signed payload 并自动重发／签名恢复 | 最终 bytes 在本地签名且校验，journal 持久最小摘要与回执；durable pending 后不重建、不重签、不自动重发，网络异常保持未知 | 05、07、12、13 |

## 4. 实施与试用门槛

编码顺序由原方案 W00–W07 调整为：文档／基准 → 网络与 SDK／Provider → 全部领域接口与页面／交易迁移 → 核心真实 dev 链与插件切片／打包试用 → 试用期间细节故障回归 → 发布清理。三入口传输探测可提前；不会要求先完成生产 HA 或完整长尾回归再开始接口编码。

可试用要求所有实际钱包接口编码迁移、普通账户资产／币转账／dApp 授权与恢复核心路径测试、可信同链三入口和可装载包成立。未具备这些证据时只报告具体已完成的文档或代码项，不以 mock 或定向编译代替试用。
