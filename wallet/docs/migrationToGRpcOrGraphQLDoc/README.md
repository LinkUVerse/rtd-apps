## 归档原方案总览与决策（完整并入）



日期：2026-10-02，北京时间。状态：**设计已对齐合并并开始实施；钱包全量迁移和浏览器验收尚未完成。**

### 结论

**建议在 `rtd-apps/wallet` 原项目内改造，整体替换网络配置、RPC 调用、数据类型与查询 Hook；保留账户密钥体系、授权通信和用户界面。** 开始实施前固定现有工作区为可恢复的只读基准。无需另建一套功能相同的钱包应用，也不长期保留 JSON-RPC 作为失败回退。

项目尚未上线，允许一次性破坏旧内部接口。真正需要新建的是职责清晰的 RPC 模块、网络配置合同和必要的浏览器协议入口。原项目的安全与交互资产继续使用，旧数据层完成替换后删除。基准是可恢复的历史记录，不是需要持续维护的第二个产品。

Sui 官方 SDK 的迁移建议针对标准应用调用优先使用 Fullnode gRPC；通用数据访问指南更强调 GraphQL 的组合查询。两者侧重点不同。本方案据钱包行为分别路由，而不要求任何单一端点包办全部能力。依据：[SDK 迁移指南](https://sdk.mystenlabs.com/sui/migrations/sui-2.0/json-rpc-migration)、[数据访问分工](https://docs.sui.io/develop/accessing-data/)。

| 入口 | 钱包职责 | 不承担的职责 |
| --- | --- | --- |
| Fullnode gRPC，经 gRPC-Web 接入 | 交易构建与新鲜状态校验、gas、模拟、执行、近期确认、可选实时流 | 被裁剪的长期历史全集 |
| GraphQL RPC | 资产页的覆盖检查与一致快照、复合筛选、历史列表、名称、Kiosk／质押展示所需组合读 | 钱包私钥与签名托管；不作为唯一提交入口 |
| 归档 gRPC，经新增协议桥接入口接入 | 明确摘要／checkpoint／对象版本的长期详情、Move 描述、已支持的历史 List | StateService、TransactionExecutionService、NameService；不为浏览器新增这些业务服务 |

保持 [01 总体架构与职责](/Users/changzechuan/WenchuanProjects/RTD-Blockchain/rtd-archive-service/docs/architecture/01-总体架构与职责.md) 的边界。GraphQL 可以调用 Fullnode 和归档后端；客户端也可以显式直读归档。**服务源组件没有内置 gRPC-Web，属于既有边界；本方案为 Chrome 直读规划协议适配，不能把它写成已经完成的服务能力。**

### 本轮已授权采用的实施决策

1. 采用原项目改造，发布目标移除 JSON-RPC 网络依赖；同一个钱包构建只运行一套 RPC 数据层。
2. 保留 Chrome 插件身份、账户库、派生与签名流程；批准旧 RPC 内部 DTO、单 URL 网络配置和旧 Hook 的破坏性替换。
3. 采用明确路由：写与近期确认用 Fullnode；页面一致读／复合索引用 GraphQL；长期详情用归档。
4. 为归档新增开源 gRPC-Web 协议桥接，复用公开查询信任边界；不新增钱包 BFF 或归档执行转发业务。
5. 助记词及导入私钥、转账、NFT／Kiosk、质押、历史、名称、授权与设置作为完整功能基线。已有 zkLogin、Qredo、Ledger 残留和外部法币入口逐项列出，不以“未验收”冒充已支持；详见 03。
6. 先在本地 dev 完成 Chrome 实际验收；生产阶段只调整入口与网络配置，K8s 高可用建设独立排期，不阻塞本次设计与 dev 实施。

### 工作量与长期成本

原项目路线初估 **23–38 人日**，完整新建路线约 **35–58 人日**；同样覆盖本方案基本功能，均含必要协议入口和 Chrome 验收，不含 zkLogin 成功、Qredo 远程系统或生产高可用。估算来自源码范围和工作包，不是实测完成时间；先用第一个真实三入口切片重新校准。

原项目可以通过删掉旧数据层获得低债务，同时减少账户／权限／安装迁移及页面重建。新项目也需要解决同样的 SDK、归档传输、质押与历史语义问题，多出的工作主要是重新接入原项目已经具备的安全和交互能力。部署端点数量由目标架构决定，新项目本身不会降低链与归档运维成本。

完整达成的定义是：发布构建无需 JSON-RPC，三个查询入口在 Chrome 中可用，功能矩阵全部有证据，交易不确定状态可恢复，错链／缺覆盖不能被呈现为零余额或完整历史。详见 [06 的验收门槛](./07-落地批次与验收清单.md)。
