# C341：published 批量上传的精确续传

C317 已完整恢复并读回 537000 个对象后，在下一批 PUT 中收到 `ProtocolError`。实际错误栈的内部原因是 `socket.timeout: The write operation timed out`，发生于 TLS `sendall`，不是响应读取超时。当前部署 helper 的 connect=5 秒也用于发送请求体期间的 socket；仅加长 read 超时不能消除这类批量上传中断。

C341 继续使用同一源和既有 C120 bucket，复用 537000 个完整批次证据，不增加容器或改变发布水位。未完成批次逐对象核对结果：**942 个已经成功，58 个缺失**，仅补写后者。随后又出现一次模糊写入，辅助工具再次核对 **882 个已经成功、118 个缺失** 并补齐，恢复继续推进。每批只有全部固定 VersionId 和完整字节验证通过才产生完成记录。

原 C317 `failure.json` 内容逐字节保存在原目录的 `original-C317-failure.json`，SHA-256 为 `51cc6409fd0fe861cba0f21a326b77901629e26ffb00da81df59b20a1be13fb7`。原始 C317 进程已失败退出，并没有被记为自然成功。新增 `active-successor-C341.json` 明确当前执行者；共享数据目录的活动失败标记在交接后撤下，使 C337/C340 能继续消费同一组严格核验的批次。后续若 C341 失败，会同时写回共享目录的活动失败状态。最终共享 `copy-complete.json` 必须由 C341 完成全部字节、metadata 和版本清单后产生，并明确标注真实执行者及原 C317 finalizer 未成功。

该处理没有删除失败事实或放宽完成条件。它减少了依赖方不必要的重启，也避免把一次请求返回不明当成“全部未写入”后重复覆盖。

当前主范围认证下载已超过 90%，副本核验已越过此前卡住的 14000 批次。C332/C335 继续等待完整来源资格；本工作不关闭新的完整子包。
