# C316/C317：版本保真批量恢复提速

C315 逐对象 PUT、固定版本 GET、最新 HEAD 的前 7,000 个对象真实完成，后续预计耗时仍长。C316 在既有 C120 MinIO 的两个独立测试 bucket，使用同一批 200 个真实归档对象，对比逐对象与 MinIO 原生 tar 批量恢复。PAX 的 `minio.versionId` 保留原版本；两组每个对象均真实 GET 全字节、HEAD 版本及完整版本清单核验。

[实际结果](./20261012-C316-bulk-version-probe-01.json)：四线程逐 PUT 1.3262 秒，批量 PUT 0.4042 秒；含全字节读回 2.8901 秒对 1.9015 秒。两个临时 probe bucket 的已核验原版本全部删除，空 bucket 删除，无新增容器。小批结果不能直接当作 795,320 个对象的实际提速。

C317 后继将复用已完成 C315 逐对象证据，以原生批量写入继续剩余数据。只向命令和出生时间已核验的自有 C315 进程发送中断，等待线程池退出；可能已写但尚未落批次回执的对象必须在后继中逐一读回并确认原版本／SHA，不重写已存在对象。旧失败与旧源保留，后继使用独立操作目录；旧批次摘要、源冻结快照、目标初始不存在证明和 C316 结果共同绑定。

新批次写后从当前对象直接 GET，要求响应 VersionId 与原快照版本相同、字节 SHA 相同，从一次读取同时验证最新版本和内容；无需再发一次重复 HEAD。最后完整 ListObjectVersions 核对全部 checkpoint 和 metadata 集合，不省略旧版本／删除标记检查。此优化不改变正式发布水位，不修改源对象，不将后继启动计作完整归档或父项完成。
