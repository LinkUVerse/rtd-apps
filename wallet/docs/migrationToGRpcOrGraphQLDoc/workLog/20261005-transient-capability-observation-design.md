# NET-04／TX-01：瞬时窗口被动能力观察生命周期修复设计

当前C10的新UI／worker真实校验与NC5 default native正常完成已通过，但两个实际签名失败profile只读均pending1／fault0；第三次0模拟，第一次3模拟后未返回。批准／连接窗口会在正常操作中关闭，而每个Provider都启动24范围NC5，取消按既定规则保留原pending；这与前台短生命周期不相容。先保存三原源码，补生产Provider定向复现／测试，再编码最小scope调整。

P1：能力观察与数据／后台授权区分。持续页面仍独立观察NC5；dapp connect/approve准确路由及浏览器toolbar瞬时popup不自动启动完整被动NC5，明确phase unavailable/policy／readiness not-assessed，不复用任何别处正报告。P2：每个窗口仍有真实owned Session／native gate、订阅／焦点／可见性／定时负面重读及查询撤值，所有业务reader身份／快照／覆盖检查、默认native身份／固定BCS Move门槛、sign/execute账户／权限／原journal及最后负面重读都保持。此policy只控制被动评估，不接收dapp参数，不控制任何后台授权。P3：StrictMode不创建被动NC5 ticket／不发其探测IO，保留独立资产快照读取、旧pending和已知错链仍拒绝且不删除、可选Display负面不影响独立余额、切换到持续页面开展fresh评估；保留此前正常／取消／迟到／原ticket测试。P4：完整钱包与类型／新构建／所有原字节证明，再复核7原journal和fresh真实只签名。所有失败、native rows和旧C10产物保留，不清空原观察库或把未完成票据过期／变成empty完成。

这不是旧pending恢复政策；持续窗口在已begin后被关闭仍按原规则保留未知pending，其安全恢复另需独立协议。真实发布签认、最终原子授权、正常CA／全业务试用保持待验。
