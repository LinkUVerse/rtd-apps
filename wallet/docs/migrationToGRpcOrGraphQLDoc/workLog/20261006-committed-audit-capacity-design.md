# 已发布前缀复核的并发容量候选

当前 publisher 使用 4 个复核 worker。原 256-checkpoint 的 4／8 对照已通过，但不是百万前缀成本证明。本批在原 publisher 正常工作时，先做有限只读实测，不改 live 代码／参数、不发信号、不清 pending 或 epoch。

- [x] P1 生成私有候选，仅将复核 helper 的 1–8 上限扩大到 1–32，逆变换逐字节还原原文件；检查过程、顺序、版本、哈希、完整前缀和错误传播全部保持。
- [x] P2 最新 debug verifier 从原 genesis 认证 0–4095；只读 SQL 固定已发布行、实际 local／MinIO 固定 VersionId 与最新版本校验。原 8 worker 前后夹住候选 16／32 两轮，各完整 4096 项。
- [x] P3 各 8／16／32 均拒绝 staging／published 错 VersionId，共 6 案；4 个非法容量拒绝，原源代码／debug／scope 保持。
- [x] P4 [有限实测](./20261006-committed-capacity-01.json)为 8／16／32／8 各 10.347／10.177／10.494／10.208 秒，提高至 32 无明显收益，因此不安装候选、不改 live 参数。当前仍为 4 worker，不能声称管线提速；完整 namespace／百万前缀仍单独验收。

证据范围只读样本、当前并发负载下的有限耗时；不能据缓存样本保证全前缀或生产部署收益，也不能以旧历史验证跳过每个对象的完整检查。
