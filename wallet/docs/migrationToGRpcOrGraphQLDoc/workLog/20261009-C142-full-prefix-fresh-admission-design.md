# C142 完整固定输入的新鲜授权源

前置为C141所有0–709569原始正文/SQL/双端版本和完整连续quorum认证与独立审核，缺一不得监听或切换；不是换成旧有限区间。当前C139保持。已有MinIO客户端和PG连接池都已存在，本批不把重复构造客户端当作当前事实。

完整固定源码沿用既有认证输入服务：仅完整membership中的规范正文，每次真实只读TLS SQL事实、源和replica最新VersionId/复制状态、正文SHA、再次SQL/HEAD以及真实mTLS namespace授权；metadata仍返回原guard新鲜正文。原认证只证明不可变数据身份，绝不提供后续权限。

为提高多个消费者重建速度，待验证共享一次“同时在途”namespace观察：只汇集已经完成自身输入核查、同时等待权限的请求，最多4个、最多10ms收集；授权开始前冻结成员并从pending队列移除。授权开始后新请求必须创建另一组，已完成组不得再次加入、没有完成授权缓存。每个组都真实调用原guard /authorize；每个请求在自己的起止区间内取得该原guard观察，并在取得观察后独立再次核对SQL/双端HEAD和正文SHA，2秒内完成后续核查，否则拒绝。source/H0/完整范围/CA/角色固定；新源任何失败必须空503且不扩大成员或数据范围。

并发协调器先用实际线程验证边界、封组后迟到请求、并发失败广播、完成结果不能复用、时效及跨PID拒绝；这是隔离协调逻辑，不计真实namespace/全源验收。随后必须以完成的C141完整证据和当前真实guard做全原帧/并发/权限/范围/损坏差分，观察每个HTTP调用与真实授权事件的时间包含关系；如果不能证明相同权限语义和收益，就不安装。

当前adapter 4名额、三消费者各1名额、全23/14/8CF及四watermark/709569边界先保持。不基于预测扩大并发，不缓存positive admission，不更改或停原guard/链/索引/发布者。只有真实端到端差分和来源审核通过后，才按确切自有adapter的正常切换、显式出生身份接续与观察重新注册推进；完整查询重放/规范比较及父合同不缩小。NFT专项验证后置。
