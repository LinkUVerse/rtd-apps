# C308–C310：活动页读取等待修复

## 原因与已部署改动

C308 普通 C51 Chrome 活动页刷新实际等待 33.80 秒，完整周期为 5 次 GraphQL 和 1 次 GetServiceInfo。生产 wallet reader 对原始抓包的历史窗口、三笔原交易、摘要顺序和读后校验全部通过；下一轮单独的 coverage 请求不算完整读取。

定位发现 G4 账户 reader 缺少此前 G3 已验证的 `publicationAdmissionEndpoint` 与 `internalGraphqlEndpoint` 配置，11 次内部 GraphQL 查询都会再次走外部发布准入。C310 沿用已有生产 `AdmittedPage`：一页读取开始和结束各做一次真实准入，所有内部 GraphQL 请求携带首次已验证的发布上界。没有改动产品源码、关闭认证或缓存旧准入成功。

同一固定窗口 0..24478 的三笔历史做两组交错比较，完整响应内容相同：原配置 11.337 / 11.171 秒，候选 3.271 / 2.871 秒。候选仍有 11 次内部 GraphQL，另有 2 次直接准入；减少的是每次内部查询背后的重复准入工作，不能将 13 次直接调用描述成少于 11 次。6 项现有页级准入回归通过，包括最终准入失败/水位倒退拒绝、错链和非法上界拒绝。

实际部署仅替换 G4 账户 reader 及关联摘要，保留全部原件，对原账户 API master 99345 发出一次 SIGHUP，确认旧 worker 退出、新 worker 读取新配置；原 master、监听端口、账户、链、发布器和全部容器保持。部署后同一固定页返回内容完全一致，用时 2.001 秒。

## 普通 Chrome 复验和限制

两次刷新后均显示原三条交易，最新支持窗口为 0..24657。第一轮完整周期约 10.16 秒、第二轮约 8.77 秒，但 HAR 分别给一个已返回 HTTP 200/正文的请求附加 `net::ERR_ABORTED`；这两轮不计作完整无取消成功。第二份抓包的后续完整轮询周期 **11.76 秒**、5 次 GraphQL、没有错误或取消，已通过生产 reader 对全部内容和读前/读后条件的重放审核。

原取消帧及一次“要求全部无错误”的审核失败保留；后续审核明确验证取消帧被 reader 拒绝，未将带取消标记的正文冒充成功。异步浏览器调度未被离线重放复刻，本次不宣称永久消除取消或长期稳定性。浏览器控制台还显示既有 Ampli 未初始化消息，此轮没有将它归因于 RPC 失败。
