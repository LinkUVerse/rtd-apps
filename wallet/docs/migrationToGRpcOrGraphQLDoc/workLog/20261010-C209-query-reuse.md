# C209 全页面查询复用

用户要求所有页面尽可能减少GraphQL/gRPC请求，能复用的一律复用，不统一限制总次数。禁止跨链/端点/会话复用、持久化旧准入或减少资金操作检查。

设计：优先合并同一调度窗口的轻量GraphQL独立查询，使余额和元数据仍独立校验及处理错误；完整资产/Display与复杂领域保留故障隔离。gRPC身份只合并尚未发出的同会话请求，保证读取后复验发生在读取之后；不缓存已完成的身份结果。路由按真实快照消费者决定预加载，未知路由保守保留。

进度：代码、真实服务、构建审核和用户批准安装完成；普通 Chrome 首页性能验收发现异步本地准入导致仍为 8 GraphQL，未计通过，继续 C210 修复。


## 页面依赖盘点与实现

| 页面 | 读取需求 | 实施策略 |
| --- | --- | --- |
| 首页、币种详情 | 余额/元数据；可选活动模块可能读NFT | 轻量查询合并，NFT组件真正挂载时按需申请完整快照 |
| 发送、币种选择 | GraphQL余额/元数据，Fullnode新鲜coin/balance | 取消无用Display预加载；并发Fullnode身份请求合并，资金准备/模拟/执行不改 |
| 质押列表/数量/详情 | 独立staking快照、元数据、Fullnode可用余额 | 无Display预加载，保留完整质押系统/仓位/汇率读取 |
| 活动 | 独立账户历史/交易明细；可选NFT缩略图 | 无条件预加载移除；缩略图查询按需申请完整快照 |
| NFT/隐藏资产、Kiosk、NFT详情/转移 | 完整资产Display快照 | 保留预加载和校验，相同并发查询共享 |
| 收据 | Ledger明细及共同索引水位检查 | 保留快照；同会话/端点/期限的GetServiceInfo合并 |
| 账户、应用、入金/推广页面 | 本地状态或页面明确请求 | 无通用资产预加载，仍支持按需请求 |
| 授权、未知路由 | 复杂动态内容 | 保守保留预加载，资金授权协议不改 |

路由并非永久禁止资产查询：Provider订阅本session的wallet-assets活动observer，出现真实需求时启动共享准入和轮询；移除需求后停止该轮询。openAssetSnapshot首次按需请求复用React Query正在运行的准入；失败不会自动无限重试。新增实际Provider测试验证无预加载时NFT/拥有对象/批量对象均正常读取且仅一次完整准入。余额不因资产失败被撤下。

GraphQLSnapshot公共层将同一microtask内轻量余额/元数据查询合并成一个普通GraphQL文档；各原查询的变量、根alias、fragment独立命名，响应恢复原结构后继续原H0/S/digest/coverage/终页校验。可归属字段错误仅影响对应领域；无法归属的文档错误/根null只拆分重读一次，不把错误当空集合。重型资产/Display与不同领域不混在同个批量中；其完全相同且尚未发出的查询才共享。已发出/已完成结果不复用，无固定查询总次数上限。

gRPC复用限Fullnode、Ledger、ArchiveObject和ArchiveCheckpoint只读reader的GetServiceInfo。同一session、端点、原fetch及期限方可合并；每个调用方独立取消，全部取消才中止底层；读取后校验不沿用读取前已发出的请求。独立网络能力探测/授权、交易准备/模拟/执行继续原路径。原生响应帧/业务trailer、各readerH0/窗口校验保持。
