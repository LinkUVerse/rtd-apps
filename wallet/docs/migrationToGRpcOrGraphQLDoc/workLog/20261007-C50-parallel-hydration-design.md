# C50 未发布尾段缓存并发候选

原 publisher 处于 working、pending 尚未完成；无 child 不能作为安全切换窗口。本轮仅准备隔离候选，不改原发布器、既有五封存控制器、候选计划或生产缓存。

实施顺序：

1. 封存原 hydrate_source 源码；将其每序号的全部 fresh staging HEAD、固定版本 GET、旧缓存比对、历史保存、fsync、原子替换与符号链接拒绝语句逐行保留，只把循环内 continue 改为任务 return。并发最多16，每批最多16个任务；失败或取消必须等待已启动任务退出，调用方不得进入 native verifier／SQL／marker。
2. 检查未发布缓存更新、已提交跳过、固定版本捕获、释放响应连接、缺失／未版本化／GET错误、缓存和历史符号链接、历史摘要冲突、并发错误排空与取消，以及参数边界。
3. 使用原 scoped publisher 身份、verify-full TLS 和单独连接池，对256个未发布序号作1／16／16／1轮真实读取。每轮仅写本轮私有新缓存，核验原HEAD与GET固定版本、字节摘要相同及原环境／1015保护文件保持；不写对象或数据库，不复用正式缓存，不部署。
4. 只有真实样本至少1.20倍且独立审计通过才形成下一候选建议。样本通过不等于全前缀 native 认证、生命周期切换或写后524022覆盖；仍需单独集成与自然安全窗口，原98父合同不降低。
