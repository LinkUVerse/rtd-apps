# C34 交易身份观察的可恢复归属与实际结束

真实C29/C30取消场景已发现：交易身份观察仍使用未标记的begin，取消可早于忽略abort的fetch/body/cancel清理结束，留下无法安全收尾或冷恢复的占位。旧无marker记录必须保持，不能删除来制造成功。

- [x] R1：当前交易身份三入口只读观察使用同ticket的原生owner锁和严格marker。冷恢复仅采用同areas、有marker且原owner已消失的原ticket；全部其他pending/fault继续阻止授权，未标记历史占位不能采用。
- [x] R2：所有原始fetch/body/cancel清理纳入实际工作生命周期。取消立即拒绝授权，但原始工作未结束仍保持占位；实际结束后仅收尾原failed观察，不返回正面身份或执行能力；迟到明确负面与存储失败按原合同保留。
- [x] R3：真实SDK控制流、忽略abort/延迟body cancel、失败提交与冷恢复的定向测试和原生Chrome owner/IDB验证；全量测试、类型、独立生产闭包。
- [ ] R4：当前coin/NFT/staking/dApp全入口实际取消/冷恢复/竞争与完整TX-04最终验收。

交易Move ABI观察是否存在同类生命周期缺口先审计，独立证明后处理。不能仅对catch调用complete([])，不能依据超时、PID消失或界面显示推断旧工作已完成；不得抹除历史失败或扩大身份观察为签名授权。

R1–R3按有限范围完成：4项新实际SDK请求/响应清理测试、86项既有定向测试、原生Chrome12项、全量2615测试、两套类型、独立生产构建及完整闭包通过。见`20261006-C34-coding-verification-01.json`。原生测试使用独立合成只读协议和真实IDB/owner锁，未打开原生产数据库，不能替代R4实际钱包全入口。首轮响应流夹具重复释放、原生夹具未处理入口失败及marker字段错误均保留；修正后的测试使用新的结果文件。

交易Move ABI观察审计仍发现普通begin及取消后的物理清理缺口，尚未修改该路径；按独立子清单继续处理，不能以身份路径修复覆盖。
