## 2026-10-06：读取观察的原生所有权接管

仅读取能力观察使用本协议。独立 NetworkAdmission v3 原子保存 admission-v1 原票及 capability-owner-v1 标记；标记精确绑定 UUID、完整 binding、原区域及新 incarnation。原 v1／v2 admission、egress 和所有 Fault 不重写。观察者先取得该票的原生独占 Web Lock，再提交预留；锁覆盖全部原始请求、body、异步物理清理及 durable completion。活跃任务的取消通知、已过去时间和 lock query 快照都不能代替终态。

页面销毁或正常浏览器重启后，后继必须用原生 ifAvailable 取得同一票锁，并在 strict IDB 事务重新核对原票／本协议标记／binding／区域及其它负面和 pending，才可换 incarnation 接管原票。接管不删除 pending，不接纳旧快照、不发布正面报告，必须重新执行生产身份和能力观察。最终完成重新核对 incarnation，原票和 marker 原子删除，Fault 单调合并；旧 incarnation 提交拒绝。接管后的瞬时空失败在所有原始工作结束后释放持锁，但保留原票待下一次真实观察。

未标记的未知旧 pending、损坏或错误 binding／区域标记、存储失败及其它活跃票仍拒绝；不使用 TTL、steal、全库清空或空完成替代新观察。本协议不接管交易观察或 execution journal pending，不提供签名、派发或跨链授权。旧“仅原对象拥有者可以消费 terminal-failure”合同仍适用于原凭据；后继不伪造旧凭据，只取得新 incarnation 后重新观察和持有自己的生命周期。

依据：[Web Locks 2.4、2.6及request](https://w3c.github.io/web-locks/)的waiting promise、document卸载释放和原生ifAvailable授予语义，以及[IndexedDB严格事务](https://www.w3.org/TR/IndexedDB-3/)。已验范围包括原生合成命名空间的v1／v2保留、两页面、真实页面销毁／正常浏览器重启和迟到错链；当前C28实际扩展普通浏览器重启13项证明同原票新incarnation接管并恢复fresh完整余额，实际reload9项证明重新读取且无遗留标记。reload时原生取消也可能合法结束原观察，不能强制每次刷新都必须接管。独立字节与原帧审核见钱包workLog/20261006-C28-observation-owner-completion.md；任意物理崩溃、BFCache和全QA仍需核验，规范不代替产品运行证据。

## 2026-10-06：失败观察的原拥有者收尾合同

取消通知和 wrapper rejection 不证明 fetch／body／异步 cancel 清理及领域 raw work 已结束。仅本次原 ticket 的进程内拥有者可以在全部工作结束、后续 IO 已封闭后消费一次性、不可序列化的 terminal-failure 凭据；原严格 IDB 事务只移除自己的 pending，单调保留 identity／schema／ABI Fault 和其他 pending。收尾不会发布正面能力或授权新动作；新动作仍需当前身份、依赖和最终准入。

begin 失败、存储 abort、失去原对象所有权、克隆／重放凭据、崩溃留下的未知旧 pending 均保持拒绝。不得用 TTL、新正面结果或空完成直接清旧 pending。已确认 Fault 后取消也必须保留 Fault。该明确收尾协议与历史“取消未知状态不删除”保持一致：未知／在途状态继续保留，仅有原拥有者完整结束证明的失败观察可结束预留。

规范依据：[WHATWG DOM AbortSignal](https://dom.spec.whatwg.org/#interface-abortsignal)、[IndexedDB 事务完成](https://www.w3.org/TR/IndexedDB-3/#transaction-finished)。[E8 编码前设计](./workLog/20261006-observation-terminal-settlement-design.md)记录原生 strict IDB 和实际产品回归范围；有限 fixture 和历史 C17 实签不能代替 C18 真实网络切换接受。

```typescript

  id: string;
  displayName: string;
  sdkNetwork: string;                 // SDK Network 接受任意 string
  walletStandardChain: string;        // 明确注册的 rtd:... 标识
```

字段结构供实施采用；是否开放更多 deployment metadata需保持scope明确。配置不包含私钥、管理凭据、HBase／PG／MinIO地址或长期服务端共享密钥。完整内置网络三入口必配；可选字段用于自定义／明确降级网络，不是把内置钱包功能削减为只显示余额。

Faucet 是独立 HTTP 服务，不是 JSON-RPC 替代查询入口。当前 RTD／SDK 使用 POST `/v2/gas`，profile 的可选 `faucetUrl` 只接受 origin（SDK 会从根路径解析 `/v2/gas`，不接受被静默丢弃的路径前缀）。不再按 devnet／testnet 标签推断地址。发币前重新核验当前 Fullnode 的完整 H0，预检期间账户／profile／会话变化则不发送；Faucet 本身无链身份接口，Fullnode 预检不冒充 Faucet 身份证明，其部署对应关系须由受控配置保证。Faucet URL 纳入配置绑定键，缺失不使用默认服务，网络不明确时不能自动重试发币。

## 2. 身份握手与能力探测

### 2.1 当前本地 SDK 身份合同

**此版 SDK 的 getChainIdentifier 返回完整 genesis checkpoint digest，而不是旧 JSON-RPC 的短标识。** types.ts注释明确是32-byte base58；gRPC core取GetServiceInfo.chainId，GraphQL core查checkpoint(sequenceNumber:0).digest。不得从早期SDK经验擅自截断或按十六进制转换。

Wallet Standard中的 `rtd:devnet`、`rtd:localnet`等是账户／dApp兼容标签，并不证明chainId。保存标签到expectedGenesisDigest的明确映射；自定义chain须使用支持的注册映射并在demo中测试，不能用现有`rtd:unknown`默认允许任意链。

SDK身份查询有cache；换endpoint／generation必须重建client并再次网络查询。不能一直复用缓存中的H0判断dev尚未被重置。

### 2.2 握手步骤

1. 校验URL：HTTPS生产、localhost／127.0.0.1 dev例外；禁止URL username/password、fragment、任意动态redirect到未批准origin。GraphQL路径与grpcbaseUrl分别规范化。
2. 检查Chrome host permission与TLS；读取三个入口的实际身份。Fullnode／archive通过Ledger.getServiceInfo＋必要H0点查，GraphQL通过H0 digest。
3. 与expectedGenesisDigest精确比较；自定义第一次绑定时先展示真实身份并由用户确认，不把未验证字段写成trusted。
4. 检查服务可用方法／schema及协议版本、所需管线coverage；无业务fixture时只能证明声明／基础能力，不能声称名称或Kiosk业务成功。
5. 验证packages、registry与配置revision；有accountHistory扩展时独立校验它的chain、scope、覆盖和证书旗标。
6. 构造全新clients／queryscope，进入就绪或明确降级状态；保存验证时间和摘要，不把探测异常变为空数据。

握手使用临时只读客户端或raw探针；其未验证身份不进入页面缓存、signer或执行路由。验证完成后才发布活动客户端集合，避免“为探测必须构造client”被误解成允许在握手前执行交易。

探测不能用“不存在对象返回null”来证明State／Name服务支持，也不需要每次页面打开执行一笔交易。部署签认＋轻量身份／schema探测＋实际功能回归各自负责不同证据层级。

### 2.3 网络状态与故障策略

| 状态 | 页面／执行 |
| --- | --- |
| unconfigured／permission-required／validating | 显示配置或连接状态，禁用执行；不显示新网络0余额 |
| ready | 内置完整网络已通过所需身份及能力检查 |
| degraded | 某个已验证同链入口暂不可用；对应功能标不可用。Fullnode身份仍有效时可保留普通执行，不能让GraphQL临时落后阻塞一切操作 |
| chain-mismatch／reset-required／incompatible | 丢弃客户端可用性结论，禁用执行及新数据提交，要求正确绑定／更新 |

“一个入口暂时不可用”与“已发现入口属于另一条链”不同；错链必须整体停止可能混淆的内置网络操作，不用降级绕过。

## 3. 水位与同一读取会话

### 3.1 不同水位不能互代

| 水位 | 含义与用途 |
| --- | --- |
| Fullnode 最新高度／最低保留 | 链头与近期读取范围；不是归档索引完成证明 |
| archive GetServiceInfo.checkpointHeight | 所有必需已提交KV流水线的最小水位；作为共同已覆盖的可读上界，最早保留位置另按 readerLo／最低可用字段核验 |
| GraphQL availableRange(type,field) | 每个读取字段真正覆盖的区间；组合查询取交集 |
| 已验证发布上界 | 服务端可信公开门禁；钱包不能自行设置或扩大 |
| accountHistory证书／snapshot | 自定义领域索引窗口与完备范围；不是全链所有对象的总证明 |

资产读取会话依赖balances、ownedObjects、metadata、checkpoint等具体查询字段。先读每项实际availableRange，令 `Lo=max(first)`、`Hi=min(last)`，`Lo<=Hi`后选择S并读取digest。所有页绑定S／digest／owner／filter，结束时重验coverage与snapshot事实。保留既有archiveSnapshot及失败关闭，不用单一checkpoint页通过就承诺全部字段覆盖。

GraphQL服务按atCheckpoint支持的字段固定快照；新SDK普通顶层listBalances等未提供所有snapshot参数，完整portfolio优先用现有原生GraphQL适配，不能假设单个client自动冻结整个多请求会话。

原生快照实施合同（2026-10-03 对齐）：使用 `checkpoint(sequenceNumber: S) { sequenceNumber digest query { ...领域查询... } }` 固定整个领域查询树，而不是对 SDK 顶层调用添加不存在的参数。`availableRange` 位于 `serviceConfig`，按 type／field／filter 逐项读取；准入取覆盖交集，后续每页同时重验 H0、S／digest、全部依赖覆盖，终页再复验后交付。首个 cursor 自带的一致性只固定其分页流，不能替代不同查询树之间的共同 S。地址／coin type／对象 ID 与金额也需按请求合同校验；部分 `data + errors`、缺必需字段、重复项、无进展 cursor、预算截断均不交付资产全集。

权威依据：[Sui 官方 checkpoint scope 与 retention 说明](https://docs.sui.io/develop/accessing-data/graphql/query-with-graphql)、[Sui 固定提交 SDL](https://github.com/MystenLabs/sui/blob/c860146823abcedef45a1b5a9c766920be98a29c/crates/sui-indexer-alt-graphql/schema.graphql)。钱包保留该 SDL 的哈希与原文于 `evidence/official/sui-snapshot-manifest.json`；受控 Fetch 测试同时按该官方 SDL 和本地 RTD SDK SDL 校验查询（仅将地址 scalar 名称 RTD→Sui 对齐）。这属于协议形状与故障测试，仍不等于部署入口运行／Chrome／可试用验收。

### 3.2 x-rtd-min-checkpoint

只给归档gRPC请求，十进制u64，H0有效；省略即无最低下界。值来自同链先前观察水位最大值，或已确认入链交易的实际checkpoint；不来自Sui主网高度或任意“安全大数”。

- 服务达到下界才放行，未达到在预算内等待，超时Unavailable可重试；非法／溢出InvalidArgument。
- 不固定读取快照，也不改变历史选择器；服务水位H100仍可GetCheckpoint(0)。
- 客户端下界不能突破认证发布上界；钱包不得发送可信`x-rtd-visible-checkpoint`。
- raw service call可用 `{meta:{'x-rtd-min-checkpoint':decimalH},abort:signal}`；native服务的metadata合同也适用于桥接后请求。
- portable Core options只有signal等，不能传未声明的meta。调用具体历史操作时走raw wrapper，或实现基于当前SDK transport的受控metadata注入；并发请求不得共享可变header导致错水位。
- 不把此头套给Fullnode或GraphQL假装同样生效。发送后等待GraphQL索引使用coverage，而非该归档头。

| 新genesis重建 | H0 digest改变，停止旧会话、clients、watermarks、cursor、package／registry缓存与endpoint绑定 |
| 相同genesis清空后重建 | digest可能不变；reset流程更新generation，钱包显式清理对应会话和旧水位 |
| 只重建归档，主链历史未变 | 同链旧下界仍有效；归档需补追，不随便把原下界清零绕过一致性 |
| 端点未经配置却高度倒退 | 摘除该入口并重验；不要自动认为reset完成而继续花费 |

generation是RTD部署／dev流程字段，非Sui官方最低checkpoint头的一部分。钱包没有“重置链”权限；收到受控新profile后才切换，不能仅因为一次请求失败就自动清空身份或journal。

旧pending journal按chain／generation保留为隔离的历史记录，不当作新链已失败或删除密钥。账户地址可保持，资金和包在新链重新生成；相同地址不证明沿用了余额。未来公网链generation稳定，由配置版本管理。

## 5. 缓存与并发

### 5.1 键规则

```text
客户端实例：profile.id + revision + chainId + generation + endpointFingerprint
领域query：以上 + accountAddress + operation + normalizedFilter + include + snapshot
pagination：领域query + endpointRole + cursorCodec + range + snapshotDigest
执行互斥/journal：chainId + generation + account（不含URL或别名）
```

SDK缓存按client隔离，网络改变重建；TanStack缓存不可跨chain／generation复用。UI仅重置queryClient不够，还必须abort旧请求、清除signer/client实例、释放流，并用sessionRevision拒绝迟到响应。

持久查询缓存使用 `queryClient.wallet-grpc.v2` 与 `wallet-grpc-v2` buster，旧 `queryClient.v1` 保留但不再读取。所有 `wallet-` 领域查询及标有 `skipPersistedCache` 的查询不参与持久化，禁止持久化任何 mutation（包括暂停中的提交）；仅成功的普通非链查询可以进入该缓存。交易的待确认状态仅由执行 journal 恢复，不从 TanStack mutation cache 重放。

### 5.2 提交页面状态的原则

- 页数据、去重集合和nextCursor原子更新；链／范围／schema／顺序／计数任意失败，不改变已接纳state。
- 不同来源页不拼接成一个continuation，刷新从新会话开始。历史详情用digest可复用领域事实，但来源证据、snapshot和链仍需核对。
- 保留上一成功快照时显示其过期／同步状态，不能声称实时；只有用户明确进入Fullnode当前状态视图时才另开会话。
- read retry为有界指数退避＋jitter，建议最多2次；InvalidArgument／错链／权限／schema错误不retry。具体等待预算通过切片性能测量校准。
- 全部余额／持有集合需要走完全部页后才替换完整集合；按页UI可展示“仍在加载”，不能宣称全集已完成。

## 6. 分页合同

| 接口 | 下一页规则 |
| --- | --- |
| listOwnedObjects／listCoins／listBalances／listDynamicFields | cursor + hasNextPage，取自相同client和绑定；不得把data.length当结束条件 |
| listTransactions／listEvents | 默认ascending；钱包倒序显式descending，下一页before=endCursor；正序after=endCursor，after与before不能一起传 |
| 原生GraphQL connections | pageInfo／edgecursor与实际first/last/after/before规则；固定S／filter |
| raw Ledger List | watermark.cursor推进，检查成功terminal与SCAN_LIMIT／CURSOR_BOUND／LEDGER_TIP；每帧先做事实检查 |
| accountHistory扩展 | 自己的snapshot／continuation与计数；不转成原生cursor使用 |

gRPC过滤扫描可能返回空／短页但hasNextPage=true。必须继续推进cursor，有总budget和无进展检测；大量空页可以暂停并提示继续加载，不能装作到达历史末尾。raw流缺terminal或异常结束时不能提交“完整窗口”结论。

默认页大小建议25，最大不超过当前服务cap（常见50）；各部署cap从配置和能力验证确认。GraphQL与gRPC超限行为不同，统一在钱包入口验证。u64在rawprotobuf中使用bigint，JSON配置传decimalstring；GraphQLUInt53查询超过MAX_SAFE_INTEGER明确拒绝／不支持，不能悄悄截断。

交易去重用chain＋digest；事件用chain＋digest＋eventIndex；对象展示用chain＋objectId＋version。digest字典序不是统一账本顺序，仅自定义accountHistory约定可使用其排序规则。

## 7. 实时连接与MV3生命周期

Chrome service worker可以被回收，内存和长Promise不是持久状态；正式事务依靠IndexedDB及受控唤醒恢复。[Chrome生命周期](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)。

首版正确性由页面查询、重开刷新与journal保证；实时流作为前台增强：

1. 页面可见时开Fullnode订阅，关闭或切网立即abort。流水线用途的长期消费留给服务端，不让钱包扫全链。
2. 保存**已处理**位置，不是刚收到但还未接纳的数据位置；处理与位置写入须防止遗漏。
3. Fullnode新事务／事件订阅从当前tip开始，不能把旧cursor直接塞入请求实现恢复。新连接先得到起始水位Cs，缓存其后帧，用配对Ledger List补 `(lastProcessed, Cs)`。
4. SCAN_LIMIT继续扫描；索引tip落后返回LEDGER_TIP需等追上再补，直至CURSOR_BOUND后才排空buffer。buffer有界，超限取消并重新补洞，不能丢帧继续显示实时。
5. checkpoint订阅以sequence number恢复，用listCheckpoints补已处理序号之后至新起点的区间，不能套transaction/event字节cursor。
6. 名称、资产与历史页重开先普通查询，不认为订阅已覆盖所有token／Kiosk领域。

依据当前SDKproto及[官方流恢复合同](https://sdk.mystenlabs.com/sui/clients/grpc#recovering-missed-data)。已有RTD GraphQL SSE若启用，有独立exclusiveafter和公开水位规则，不能与Fullnode订阅的cursor互换；本方案不要求同时维护两套实时源。

## 8. 权限、TLS与发布配置

- 原manifest是MV3，host_permissions仍有旧网络域名；Webpack虽为部分archive配置追加origin，但没有统一三入口合同。新manifest由profile需要的受控origin生成，避免只修源码URL却漏打包权限。
- localhostdev与生产manifest分开生成；自定义网络用optional_host_permissions和用户操作申请，不能默认给任意网页RPC代理能力。
- 扩展UI／worker和测试demo网页分别验预检／CORS；host_permissions与普通网页CORS规则不同，不能将二者混作一项“全部浏览器通过”。生产入口明确允许受支持请求头并限制网页origin，不使用含凭据的无条件通配。
- CSP script保持self，不加载远程执行代码；connect-src按可批准origin管理，自定义配置限制域／协议。内容脚本的all_urls用于钱包注入，不等于授权站点访问wallet网络／密钥。
- 生产公开入口不嵌入长期sharedsecret。现有dev身份认证材料由受控环境提供；如要浏览器可用认证，采用部署端批准的短期／公开查询方案，不能把管理证书或私钥打进bundle。
- 诊断导出只含版本、端点角色、chain摘要、coverage／错误码／耗时；默认去标识地址、origin和交易内容。删除WalletSigner的敏感debug输出作为迁移清理项。
- 保留现有extensionID的构建配置；不得随意改变manifest key或发布身份。开发与生产安装、journal schema迁移与回滚单独验证。

网络存储损坏处理补充（2026-10-04）：wallet_network_v2仅在缺失（storage默认null）时读取旧配置；false、0、空字符串等非法已保存值也必须报错并保留，不能因truthy判断静默回退到rtd_Env／旧URL。读取或预检失败不写回、不探测端点。


### GraphQL 快照读取的临时 HTTP 故障（2026-10-04）

GraphQLSnapshot 的专用只读 fetch 对 HTTP 408／429／502／503／504 最多重试两次（总计三次请求），请求体、变量、端点与取消信号不变。退避为 200／400 ms 加 0–100 ms 抖动；Retry-After 可见且有效时，等待不短于其秒数或 HTTP 日期，超过60秒或数值溢出则直接交还原错误响应。所有尝试及等待共用该次 request 原有超时与调用方／会话取消信号，不因重试刷新预算；该预算是每次 request，不冒充完整多页读取总预算。

HTTP其他状态、浏览器无法区分网络／TLS／CORS的fetch异常、GraphQL部分响应、schema错误、完整H0失配、覆盖或快照摘要错误不自动重试。每次成功响应仍走原有H0及快照核验。该能力仅接入钱包自编的GraphQLSnapshot查询，未接入交易提交、Faucet或其他服务；TanStack层不增加重试。跨服务并发与统一读取错误分类尚待完成，NET-11保持未完成。

HTTP等待语义依据[Retry-After规范说明](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Retry-After)；状态白名单、次数和本地退避是钱包实施策略，不宣称Sui服务承诺。SDK源码核对：rtd-ts-sdk/packages/typescript/src/graphql/client.ts 的query将signal传入fetch，并在非2xx时抛出请求错误。


### 读取并发预算实施（2026-10-04）

WalletReadSession 对已接入的 SDK 单次查询统一提供4个运行名额和64个FIFO等待名额，等待队列已满明确抛出WalletReadBudgetError，不降级为空数据。排队时间计入调用方已建立的超时，取消后立即移除等待项，已发出的底层查询即使忽略取消也必须结束后才释放名额，迟到成功数据拒绝交付。名额覆盖SDK完整响应消费，包括JSON正文或gRPC正文及trailers，而非仅HTTP响应头。

已接入Fullnode对象／余额／Coin分页／水位／epoch、GraphQLSnapshot、账户历史扩展查询、归档指定版本对象与checkpoint、Ledger交易查询及归档回退。同一会话跨这些reader共享预算；分页每页及前后身份查询各自申请，组合reader外层不占名额，避免账户历史调用原生快照时死锁。GraphQL重试及退避期间保留当前名额。

该限制按WalletReadSession生效，不是跨Chrome窗口／后台实例的全局进程配额。交易准备器SDK内部解析、模拟、执行／恢复专用reader和独立准入探测尚未统一纳入，NET-11仍未完成。执行路径未增加排队或重发。此为钱包本地资源策略，不宣称Sui官方限额。


### 交易准备与模拟的读取预算（2026-10-04）

WalletTransactionReader 的 RpcTransport.unary 已加入同一 WalletReadSession 队列，覆盖 SDK 内部交易解析、身份查询和正式 SimulateTransaction。排队前建立的会话／调用方截止信号贯穿实际请求，取消等待不启动传输；预算名额持续到完整响应、status及trailers结束。仍保留单次准备最多64次RPC的既有上限及正式模拟字段验证，TransactionExecutionService仅允许SimulateTransaction。

封装使用显式依赖 @protobuf-ts/runtime-rpc 2.11.1 的标准 UnaryCall：headers／response／status／trailers 及整体await都来自完整底层调用的结果，headers也延迟到调用结束交付；只消费response的SDK不会产生未观察的兄弟Promise拒绝。模拟仍无自动重试，执行提交不使用该封装。

验证包含六个并行真实SDK准备器全部完成且同时传输峰值为4、四个名额占满时关闭会话不发出任何身份查询或模拟。执行／恢复专用reader、独立准入及跨会话／跨窗口总配额仍待审计，NET-11保持未完成。此为本地资源策略，不是服务端并发承诺。


### 执行辅助读取与准入预算（2026-10-04）

WalletExecutionReader的前后GetServiceInfo与远程VerifySignature已接入会话读取队列；lookup／details原本经WalletLedgerReader共享同一预算。独立入口探测和三入口H0准入亦在SDK单次查询层接入。ExecuteTransaction本身保持现有一次调用，未纳入自动重试；在提交前身份查询排队期间取消时不会发送执行请求。已进入提交状态后的不确定结果继续按journal／原摘要恢复，不能因队列或网络错误重发。

### 读取错误公开展示（2026-10-04）

### 冷启动快照与写后读目标的区分（2026-10-07 权威核对）

Consistent Store 的写入与水位持久化，供按 checkpoint 读取的 RocksDB snapshot 则在进程内保存，冷启动不能承诺保留原来的快照下界。增加 snapshots 数量上限也不使旧快照跨进程持久化。依据 [Sui 固定提交源码 db/mod.rs](https://github.com/MystenLabs/sui/blob/c860146823abcedef45a1b5a9c766920be98a29c/crates/sui-indexer-alt-consistent-store/src/db/mod.rs) 与 [官方 GraphQL scope／retention](https://docs.sui.io/develop/accessing-data/graphql/query-with-graphql)。本地 RTD 同模块保持该语义；正式历史点查仍走已认证归档，不能用临时 snapshot 数量代替归档。

对于 checkpoint T 已确认的 NFT 放入或转移，验证当前索引状态应选择实际可用的共同 S，要求 S ≥ T，并在 S 的 checkpoint.query 下核验完整对象／余额／动态字段／Display 等依赖及实际内容。只有查询“恰在 T 时的状态”才要求 T 自身处于历史快照可用区间；读取当前状态不要求资产创建或放入高度仍在区间内。全部十项 ASSET_COVERAGE、H0／digest、逐页与终页复核、原生实际可用范围，以及新鲜对象身份检查继续成立，不能只看某个最高水位或改用 Fullnode 内容补齐不完整组合读。实际完成验收还须保存生产读取、真实 UI 与写后刷新证据，S ≥ T 的数字条件本身不足以宣告完成。

名称读取独立保留四项 NAME_COVERAGE 覆盖实际当前 native 高度，以及 snapshot+20 的新鲜度边界，不将某个有限追平目标或旧名称 seed 用作替代。

## 同S分页的Display证明上界

[官方GraphQL查询文档](https://docs.sui.io/develop/accessing-data/graphql/query-with-graphql)的consistent pagination与scope要求每页来自相同checkpoint；[固定Sui consistent-store源码](https://github.com/MystenLabs/sui/blob/c860146823abcedef45a1b5a9c766920be98a29c/crates/sui-indexer-alt-consistent-store/src/db/mod.rs)区分指定checkpoint读取与实际AvailableRange。RTD额外Display.historyCoverage并非Sui原字段，其连续上界来自每次读取的历史水位，见rtd/crates/rtd-indexer-alt-graphql/src/api/types/display.rs与wallet/src/shared/rpc/display-history.ts。后者已有明确约束：live upper bound允许在多页之间推进，source和S不能改变。

同S分页必须精确比较对象集合、顺序、version、digest、owner、BCS、JSON、Display.output，以及basis模板身份、来源、内容SHA和固定S/digest。只有historyCoverage.lastCheckpoint及其对应lastCheckpointDigest可因服务推进而不同；每份coverage仍须独立符合相同H0/sourceId/history generation、first=0、固定snapshotCheckpoint/digest、last大于等于S，且last的原生checkpoint/digest确证一致。不得因此忽略任何其他字段，不得以较新上界替代固定S，不修改产品proof或响应。整份动态Display证明逐字节相同不是这份语义的要求。

### 账户活动完整窗口的默认总期限（C41）

RTD账户历史reader默认采用已有60秒总期限上限，前置身份和覆盖准入、全部分页、末次复核共用同一deadline。每页不得重置计时；显式调用预算仍限制1–60000ms。达到期限时不得把部分记录暴露为完整或空历史，也不因为延长默认预算提高allActivity/allTransfers等覆盖认证。网络或账户切换、caller取消、忽略取消的迟到响应保持原关闭式拒绝。

这一选择来自本地C40 UI实际复现20秒期限错误且准入保持observed/clear，而完整非空生产分页约32秒。146项定向回归包括42秒完整两页接受、62秒整体拒绝及显式20秒拒绝。C41仅改变一个生产reader叶的默认预算；实际页面与服务健康仍独立验收，不将期限测试当业务全集证明。详见wallet迁移workLog/20261007-C41-account-history-budget-design.md及原始证据。


### NFT 收件人草稿与后台资产快照刷新（2026-10-07）

同一 H0／generation／account／readSession／对象的收件人输入草稿，在资产快照轮换导致的临时 loading／initializing／读取保护期间保留渲染。上次已准入的对象类型只维持表单实例，不能提供当前持有或交易权限：`ownershipReady=false` 时新准备与原预览批准均禁用，重新准入后仍需全部最新对象／名称／bytes／有效期及签名授权重验。首次未准入不显示可用表单，明确查询错误、确定不持有、账户锁定和真正 scope 退役仍撤销；派发结果只按原摘要恢复。

C41真实Chrome观察到相同链绑定／读取会话／表单key下，后台新资产快照使输入消失后返回为空。独立诊断与回归分别证明该问题，当前修复通过8项草稿／撤销检查及41项NFT会话／准备／持有相关检查。新生产构建、真实刷新与完整收件人矩阵的验收另行记录；编码／单元通过不代表普通Chrome TLS、全部NFT分支或98项任务已完成。


### C250 当前资金展示接入（2026-10-11）
