# 前端迁移实施方案：Link-U Mobile 与 RTD Chrome 钱包

核对日期：2026-09-24。本方案是待实施设计，两个前端的生产代码尚未修改。路径与接口均以当前本地 fork 为准；RTD 服务端点、CORS 和真机兼容性必须按 [验收矩阵](./05-验收矩阵与落地次序.md) 实测。官方依据是 [SDK 2.0 JSON-RPC 迁移指南](https://sdk.mystenlabs.com/sui/migrations/sui-2.0/json-rpc-migration)、[数据接入决策矩阵](https://docs.sui.io/develop/accessing-data/data-serving) 和 [交易构建基础](https://sdk.mystenlabs.com/sui/transactions/basics)。

## 1. 目标接口分工

| 前端行为                                                                         | 首选 RTD 接口                                                              | 服务依赖                                                                | 决策理由                                                                                          |
| -------------------------------------------------------------------------------- | -------------------------------------------------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 构建 PTB 所需对象/余额、参考 gas、当前对象、签名、提交、模拟、交易刚提交后的确认 | `RtdGrpcClient` 顶层方法                                                   | Full Node gRPC + 对浏览器可用的 gRPC-Web 入口                           | 低延迟当前状态与执行；SDK 将这些作为通用顶层方法。React Native 须先完成真机传输验收。             |
| 钱包活动/收发地址历史、按对象/函数/事件筛选、跨资源页面、历史对象版本            | `RtdGraphQLClient` 标准方法或按 schema 编写的查询                          | RTD GraphQL RPC + General-purpose Indexer + 数据库；旧详情需要 Archival | `affectedAddress`、组合筛选和对象版本超出当前 Core 的标准过滤器；索引范围和保留期要匹配产品需求。 |
| 已知交易 digest / 对象 ID+版本 / checkpoint，且早于 Full Node 保留期             | 已配置归档后端的 GraphQL；服务端也可直连 Archival Ledger gRPC              | Archival Service + 完整数据写入                                         | Full Node gRPC 没有隐式归档回退；Archival 是点查，不承担执行。                                    |
| 事件/交易流式消费与可靠回填                                                      | 后台服务使用原生 gRPC subscription + list；前端使用该服务的产品 API 或轮询 | Full Node + 持久消费服务                                                | 流订阅从当前 tip 开始，断线需按游标回填；避免把手机或插件生命周期当持久消费者。                   |
| 过渡期尚未迁移的旧方法                                                           | 隔离在 `RtdJsonRpcClient` 适配层                                           | 明确仍开启的 RTD JSON-RPC 入口                                          | 仅用于阶段性迁移；停用门槛是调用点与验收全部完成，不能把旧接口当长期生产依赖。                    |

`RtdGraphQLClient` 本身也支持交易执行/模拟，`RtdGrpcClient` 本身也支持标准交易/事件列表。上表是生产默认分工，不是协议能力边界。[SDK 标准顶层方法](https://sdk.mystenlabs.com/sui/migrations/sui-2.0/json-rpc-migration)明确 `getTransaction`、`listTransactions`、`listEvents` 可在两端使用。相反，`Transaction` 只是 PTB 构造器；[交易构建基础](https://sdk.mystenlabs.com/sui/transactions/basics)中的 `build({ client })` 会按需要向所选 client 查询数据，交易模型不决定网络协议。

## 2. 先升级依赖边界，再替换调用

当前 `rtd-typescript` 是 2.31.3，导出 `rtd-typescript/grpc`、`rtd-typescript/graphql`、`rtd-typescript/jsonRpc`；`rtd-typescript/client` 不再导出旧 `RtdClient`。证据：[SDK 包导出](/Users/changzechuan/WenchuanProjects/RTD-Blockchain/rtd-ts-sdk/packages/typescript/package.json)、[客户端公共入口](/Users/changzechuan/WenchuanProjects/RTD-Blockchain/rtd-ts-sdk/packages/typescript/src/client/index.ts)。Link-U Mobile 的[客户端工厂](/Users/changzechuan/WenchuanProjects/link-u-mobile/src/blockchain/client.ts)和钱包的[客户端工厂](/Users/changzechuan/WenchuanProjects/RTD-Blockchain/rtd-apps/wallet/src/shared/rtd-client.ts)仍导入旧类；直接把 URL 换成 gRPC 地址并不能修复编译或响应语义。

建议在各应用内部先建立**明确的服务边界**：`liveClient` 负责执行与近期点查，`historyClient` 负责索引查询；共用的查询库接受 `ClientWithCoreApi`，只用 `client.core` 中确实跨传输的 API。UI 不应在几十个组件里自行决定端点或拼接协议。客户端类型、端点、网络标识应进入同一环境配置，切换网络时同时清理 client、React Query 缓存、游标及旧链身份。不要把 Sui 官方 URL 硬编码进 RTD 应用。新 SDK 的准确导入入口见 [gRPC export](/Users/changzechuan/WenchuanProjects/RTD-Blockchain/rtd-ts-sdk/packages/typescript/src/grpc/index.ts) 与 [GraphQL export](/Users/changzechuan/WenchuanProjects/RTD-Blockchain/rtd-ts-sdk/packages/typescript/src/graphql/index.ts)。

下面只演示已在本地 SDK 声明的构造与标准读法；`<...>` 是占位符，不是已可用的 RTD 公网地址：

```ts
import { RtdGrpcClient } from 'rtd-typescript/grpc';
import { RtdGraphQLClient } from 'rtd-typescript/graphql';

const network = 'localnet';
const liveClient = new RtdGrpcClient({
	network,
	baseUrl: '<RTD_FULLNODE_GRPC_WEB_URL>',
});
const historyClient = new RtdGraphQLClient({
	network,
	url: '<RTD_GRAPHQL_ENDPOINT_URL>',
});

const { balance } = await liveClient.getBalance({ owner: address });
const total = balance.balance; // 新 Core Balance 形状；按 RTD SDK 类型核对单位
const tx = await liveClient.getTransaction({ digest, include: { effects: true } });
const finalTx = tx.Transaction ?? tx.FailedTransaction;
if (!finalTx.status.success) throw new Error(finalTx.status.error?.message ?? '链上执行失败');
```

源代码依据：[gRPC 构造器与方法](/Users/changzechuan/WenchuanProjects/RTD-Blockchain/rtd-ts-sdk/packages/typescript/src/grpc/client.ts)、[GraphQL 构造器与方法](/Users/changzechuan/WenchuanProjects/RTD-Blockchain/rtd-ts-sdk/packages/typescript/src/graphql/client.ts)、[Core 返回类型](/Users/changzechuan/WenchuanProjects/RTD-Blockchain/rtd-ts-sdk/packages/typescript/src/client/types.ts)。正式实现仍须跑 TypeScript 检查并以实际链服务验证字段。

## 3. Link-U Mobile 的迁移顺序

1. **冻结支付不变量。** [单笔原生币支付](/Users/changzechuan/WenchuanProjects/link-u-mobile/src/services/userOrders/nativePaymentFlow.ts)已经先保存订单、链身份、签名字节、签名与 digest，再广播；未知广播结果交给服务端按原 digest 查证。[批量资料付款恢复](/Users/changzechuan/WenchuanProjects/link-u-mobile/src/services/userOrders/profileBatchPayment.ts)也保存同一批次的签名与 digest。迁移接口时保留这套状态机；超时、传输断开、GraphQL 索引未追上均不得生成第二笔付款。服务端确认以原订单、原网络、原金额和原 digest 为准。
2. **先替换客户端工厂与网络配置。** `getDefaultRtdClient` 目前返回旧 `RtdClient`；把支付/模拟/当前对象调用导向 `RtdGrpcClient`。React Native 的 Fetch、gRPC-Web 响应、流式与 `AbortSignal` 行为应在 iOS/Android 真机分别验收；若运行环境无法稳定执行 gRPC-Web，可由产品后台接收**客户端本地签名后的字节**转发至 Full Node gRPC，并返回原 digest/链结果，不把私钥或未签名付款构造权交给后台。
3. **迁移链身份校验。** `getCheckpoint({ id: '0' }).digest` 当前用于支付与批次绑定，改用 `getChainIdentifier().chainIdentifier` 前，先在同一 RTD 网络上比较两值和服务端订单 `networkId`。新 SDK 类型描述为 32 字节创世 checkpoint digest；RTD gRPC 源码的 `GetServiceInfo.chain_id` 从该链标识生成。不得将缩短的网络标签或 `'localnet'` 字符串替代订单里持久化的 digest。[RTD Core 类型](/Users/changzechuan/WenchuanProjects/RTD-Blockchain/rtd-ts-sdk/packages/typescript/src/client/types.ts)、[gRPC 实现](/Users/changzechuan/WenchuanProjects/RTD-Blockchain/rtd-ts-sdk/packages/typescript/src/grpc/core.ts)、[节点实现](/Users/changzechuan/WenchuanProjects/RTD-Blockchain/temp/rtd/crates/rtd-rpc-api/src/grpc/v2/ledger_service/get_service_info.rs)。
4. **保持构造与签名顺序。** [交易构建基础](https://sdk.mystenlabs.com/sui/transactions/basics)说明构造 `Transaction` 与在线 `build({ client })` 是独立步骤。保留已签名字节和 digest；旧 `executeTransactionBlock({ transactionBlock: base64, signature })` 改为 `executeTransaction({ transaction: Uint8Array, signatures: [signature], include: { effects: true } })` 时必须显式解码并核对 digest，不在网络异常后重新调用 split/transfer/sign。`signAndExecuteTransaction` 返回 Promise 成功只表示请求完成，还须检查 `Transaction | FailedTransaction` 的链上 `status.success`。[官方交易执行映射](https://sdk.mystenlabs.com/sui/migrations/sui-2.0/json-rpc-migration)。
5. **迁移模拟/Move 返回值。** [资料查询](/Users/changzechuan/WenchuanProjects/link-u-mobile/src/blockchain/profileQuery.ts)使用旧 `devInspectTransactionBlock` 的 `results?.[0]?.returnValues`；新 `simulateTransaction({ transaction, checksEnabled: false, include: { commandResults: true } })` 返回 `commandResults`，须逐项核对 BCS 解码与错误处理。普通 dry-run 则使用 `simulateTransaction`，不要混用跳过检查的参数。[官方映射](https://sdk.mystenlabs.com/sui/migrations/sui-2.0/json-rpc-migration)。
6. **交易活动独立迁往 GraphQL。** [钱包页](/Users/changzechuan/WenchuanProjects/link-u-mobile/src/screens/online/blockChainScreens/blockChainWalletScreen/index.tsx)目前并行 `ToAddress`/`FromAddress`，但两个查询共用一个 cursor，这本来就可能遗漏或重复。新 Core `listTransactions` 只直接支持 `sender` 与 `function`；RTD GraphQL schema 的 `TransactionFilter.affectedAddress` 可取受影响地址的活动。先定义“活动”究竟包含收款、付款、赞助 gas、对象状态变化哪几类，再改用一个明确的 `affectedAddress` 查询或应用索引，不要声称它与旧两查询逐项完全等价。若仍保留两路查询，各路必须独立游标、稳定合并、digest 去重。新列表默认升序；历史页面需显式倒序和新游标，旧 JSON-RPC cursor 不可复用。[RTD Core 过滤器](/Users/changzechuan/WenchuanProjects/RTD-Blockchain/rtd-ts-sdk/packages/typescript/src/client/types.ts)、[RTD GraphQL schema](/Users/changzechuan/WenchuanProjects/RTD-Blockchain/rtd-ts-sdk/packages/typescript/src/graphql/generated/schema.graphql)、[官方查询迁移](https://sdk.mystenlabs.com/sui/migrations/sui-2.0/json-rpc-migration)。
7. **建立新响应适配器。** [旧交易呈现](/Users/changzechuan/WenchuanProjects/link-u-mobile/src/blockchain/transaction.ts)读取 `tx.transaction.data.sender`、`effects.status.status`、旧 `balanceChanges[].owner`；新 Core 结果是 `Transaction | FailedTransaction`，余额变化含 `address`。统一转换为应用自己的 `TransactionItem` 后再交给 UI，避免各屏幕只局部修补。余额、金币、对象查询也按新 Core 的 `{ balance }`、`{ objects, cursor, hasNextPage }`、`{ object }` 改写，不能沿用旧返回类型。

下面的原生 GraphQL 查询是“按受影响地址取最近活动”的**目标实现草图**，所用字段已对照当前 [RTD GraphQL schema](/Users/changzechuan/WenchuanProjects/RTD-Blockchain/rtd-ts-sdk/packages/typescript/src/graphql/generated/schema.graphql)。它只有在已部署并同步相应历史的 GraphQL + Indexer 上才有意义；返回结果还需按产品定义从余额变化和交易输入推导“收入/支出/其他”。`last/before` 与 `startCursor/hasPreviousPage` 是倒序翻旧页的同一条流，不能继续使用旧 JSON-RPC cursor。

```ts
import { graphql } from 'rtd-typescript/graphql/schema';

const activityQuery = graphql(`
	query AddressActivity($address: RtdAddress!, $pageSize: Int!, $before: String) {
		transactions(last: $pageSize, before: $before, filter: { affectedAddress: $address }) {
			pageInfo {
				hasPreviousPage
				startCursor
			}
			nodes {
				digest
				effects {
					timestamp
					status
					balanceChangesJson
				}
			}
		}
	}
`);

const { data, errors } = await historyClient.query({
	query: activityQuery,
	variables: { address, pageSize: 20, before: null },
});
if (errors?.length) throw new AggregateError(errors.map((e) => new Error(e.message)));
const page = data?.transactions;
const nextBefore = page?.pageInfo.hasPreviousPage ? page.pageInfo.startCursor : null;
```

此查询已用本地 `rtd-typescript` 的 `schema.graphql` 经 GraphQL `buildSchema/validate` 静态检查，错误数为 0；它尚未经 RTD GraphQL 服务执行。原生 `query()` 可能同时返回部分 `data` 和 `errors`，必须检查错误；`balanceChangesJson` 仍是传输 JSON，财务或风控判断应建立经测试的强类型/BCS 转换，不把该字段直接断言为旧 JSON-RPC 的 `balanceChanges`。[官方 GraphQL 客户端说明](https://sdk.mystenlabs.com/sui/clients/graphql)。

## 4. Chrome 钱包与 `rtd-apps/core` 的迁移顺序

1. **同步升级 dApp Kit，不仅是 RPC client。** 钱包[依赖声明](/Users/changzechuan/WenchuanProjects/RTD-Blockchain/rtd-apps/wallet/package.json)仍指向 `rtd-ts-sdk/packages/dapp-kit` 顶层，而当前仓库已拆为 `rtd-dapp-kit-core` 与 `rtd-dapp-kit-react`，旧 `useRtdClient` / `useRtdClientQuery` / `RtdClientProvider` 也不在新包接口中。必须给 wallet 和 `rtd-apps/core` 一起做依赖树与 hooks/provider 迁移，或明确维护一个有限期兼容层；不能只更换 `src/shared/rtd-client.ts` 的类名。官方 [dApp Kit 2.0 迁移指南](https://sdk.mystenlabs.com/sui/migrations/sui-2.0/dapp-kit)的新客户端工厂可作技术参考，但 RTD 包名以本地导出为准。
2. **替换网络配置与缓存键。** 钱包[默认环境配置](/Users/changzechuan/WenchuanProjects/RTD-Blockchain/rtd-apps/wallet/configs/environment/.env.defaults)仍指向 Sui 域名；RTD 服务地址必须按环境分别配置，且交易缓存要包含 chain identifier、账户地址、网络和协议版本。自定义 RPC URL 应校验它提供的是 JSON-RPC、gRPC-Web 还是 GraphQL，不可把旧 JSON-RPC URL 原样塞给 gRPC `baseUrl`。网络切换须取消旧请求并清除旧游标。
3. **本地签名，gRPC 提交；历史走 GraphQL。** [WalletSigner](/Users/changzechuan/WenchuanProjects/RTD-Blockchain/rtd-apps/wallet/src/ui/app/WalletSigner.ts)在客户端保留私钥和签名操作，预执行、构建所需链查询、广播与近期确认使用 live client；[按地址活动 hook](/Users/changzechuan/WenchuanProjects/RTD-Blockchain/rtd-apps/wallet/src/ui/app/hooks/useQueryTransactionsByAddress.ts)、收据、zkLogin 账户历史判断与目标地址风险提示都依赖历史语义，应由 GraphQL 的明确过滤查询或产品索引提供。别只验首页交易列表，还要验收风控提示和账户恢复行为。
4. **验证扩展运行环境。** 当前是 Chrome Manifest V3 Service Worker；生产 gRPC-Web/GraphQL 需要 HTTPS、实际响应的 CORS 头、预检与允许头、扩展 CSP/host permissions、Service Worker 生命周期下的请求取消和重试。`connect-src *` 或广泛 host permission 不等于服务端已放行跨域；上线时把权限收敛到已验证的 RTD 域名。[Manifest](/Users/changzechuan/WenchuanProjects/RTD-Blockchain/rtd-apps/wallet/src/manifest/manifest.json)。

## 5. 方法与语义迁移清单

| 旧 JSON-RPC/SDK 调用                                   | 新通用方法或专用接口                                                           | 必须处理的变化                                                                               |
| ------------------------------------------------------ | ------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------- |
| `getCheckpoint({id:'0'})` 用于网络身份                 | `getChainIdentifier()`；必要时原生 gRPC `ledgerService.getCheckpoint`          | 对照创世 digest、订单旧持久化值和 RTD 节点实际结果。                                         |
| `getObject({id,options})`、`multiGetObjects`           | `getObject({objectId,include})`、`getObjects`                                  | `{object}` / `{objects}`，字段选择与 BCS 解析不同；批量结果逐项可能有错误。                  |
| `getBalance`、`getCoins`、`getAllBalances`             | `getBalance`、`listCoins`、循环 `listBalances`                                 | 新余额字段是 `balance/coinBalance/addressBalance`；所有币种余额分页，不能丢页。              |
| `queryTransactionBlocks(FromAddress)`                  | `listTransactions({filter:{sender},order:'descending'})`                       | 仅发送者语义相近；结果联合类型与游标重写。                                                   |
| `queryTransactionBlocks(ToAddress/FromOrToAddress)`    | 原生 GraphQL `TransactionFilter.affectedAddress` 或原生 gRPC filter / 应用索引 | 非严格 1:1，明确赞助与状态变更语义；历史保留与分页必须另验。                                 |
| `getTransactionBlock`、`waitForTransaction`            | `getTransaction`、`waitForTransaction`                                         | `include` 代替 `options.show*`；失败交易也可能是成功返回的 union；GraphQL 写后读需等待索引。 |
| `executeTransactionBlock`                              | `executeTransaction({transaction: bytes,signatures:[...]})`                    | base64 解码，保存原始字节/digest，确认链上状态；未知结果只按原 digest 查询。                 |
| `dryRunTransactionBlock`、`devInspectTransactionBlock` | `simulateTransaction`                                                          | devInspect 需 `checksEnabled:false` + `commandResults`；检查 Move 返回值的 BCS 解码。        |
| `queryEvents`                                          | `listEvents` 或 GraphQL 自定义筛选                                             | 新默认升序；分页、泛型事件类型匹配及事件保留期不同。                                         |
| 钱包 `getLatestRtdSystemState`/质押/验证者收益等       | `getCurrentSystemState` 或原生服务/应用索引                                    | 不是所有旧聚合字段都有直接对应；单独核算收益定义和系统状态的 UI 依赖。                       |

这张表用于逐调用点设计，不承诺“每个旧方法在新协议中 1:1 对应”。官方 [Method mapping](https://docs.sui.io/develop/accessing-data/json-rpc-migration)只提供功能方向，明确 `unsafe_*` PTB 构造等没有一对一替换；[SDK 迁移指南](https://sdk.mystenlabs.com/sui/migrations/sui-2.0/json-rpc-migration)进一步列出过滤器、返回形状与游标差异。凡涉及历史数据的调用，还须依据 [数据保留拓扑](./03-数据服务拓扑与历史保留.md)确定是否有真实可读的后端。

## 6. 错误、分页和缓存约定

- 交易提交的网络异常不能归类为链上失败；先用持久化 digest 查证。`FailedTransaction.status.success === false` 才表示链上失败，Promise resolve 不表示付款成功。[SDK 执行语义](https://sdk.mystenlabs.com/sui/clients/executing)。
- GraphQL `query` 可能返回 `{ data, errors }` 的部分成功结果；必须检查 `errors`。HTTP 非 2xx 才按传输错误抛出。[GraphQL 客户端错误语义](https://sdk.mystenlabs.com/sui/clients/graphql)。
- gRPC 过滤查询可出现空页但 `hasNextPage=true`，继续使用 `endCursor` 推进；GraphQL 对超限 page size 报错，gRPC 可能截断。交易/事件列表显式声明升降序，游标和过滤器必须一起进缓存键。[Core 差异](https://sdk.mystenlabs.com/sui/clients/core)。
- GraphQL 索引落后于执行结果时，UI 显示“已提交/待索引”，先通过 live client 确认 digest，再等待 GraphQL 可见；不要因为活动列表暂空再次转账。[GraphQL 写后读](https://sdk.mystenlabs.com/sui/clients/graphql)。
- `getTransaction({include:{events:true}})` 经 GraphQL 最多带前 50 个事件；完整事件必须另分页/查询或使用可返回全部的 gRPC 路径，不能用截断结果做财务核对。[Core 差异](https://sdk.mystenlabs.com/sui/clients/core)。
- 旧游标无跨协议兼容性。更新游标存储版本；切换网络、账号、过滤器、排序、索引部署或 SDK 主版本时清除旧游标。[官方迁移注意事项](https://docs.sui.io/develop/accessing-data/json-rpc-migration)。

## 7. 对后端和链节点的接口要求

在前端上线前，链运营方须提供已验证的 `Full Node gRPC-Web` URL、`GraphQL` URL、链身份、TLS/CORS 配置、限流与鉴权方式、各数据层保留期；历史点查还须有 Archival Service 或 GraphQL 已接归档的证明。GraphQL 标准事务 mutation 底层仍会依赖 Full Node，不因前端只连 GraphQL 而省去 Full Node。[官方 GraphQL 架构](https://docs.sui.io/develop/accessing-data/graphql/graphql-rpc)。超过通用索引保留期的地址活动筛选，需要应用专用索引或扩展索引留存；Archival 的点查无法替代“未知 digest 的多年历史搜索”。
